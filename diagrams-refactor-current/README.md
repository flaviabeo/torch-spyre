# Allreduce after the refactor: diagrams

These scripts build `index.html` and the eight PNGs (`_light_0..3.png`, `_dark_0..3.png`) from a debug-logged run of the two-rank allreduce test on `refactor_to_collectivekernel`.

| PNG | Figure | Source |
|---|---|---|
| `_*_0.png` | How the ops reach the device | drawn by hand in `index.src.html` |
| `_*_1.png` | Stream 1, op by op | generated by `gen.py` from the logs |
| `_*_2.png` | Iteration 1, every control block, to scale | generated by `gen.py` from the logs |
| `_*_3.png` | Where the 256 bytes go | drawn by hand in `index.src.html` |

## Quick start

From any directory:

```bash
# Run on the cards, then extract, generate and render
dt-inductor/diagrams-refactor-current/reproduce.sh

# Or rebuild from the saved logs in logs/, without touching the cards
dt-inductor/diagrams-refactor-current/reproduce.sh --no-run
```

`--no-run` gives byte-identical output each time. Use it after you edit `gen.py`, `index.src.html` or the CSS.

## Prerequisites

For the run step (skipped with `--no-run`):

- At least 2 Spyre cards and the usual Spyre environment (senlib, flex, spyre_comms, `AIU_WORLD_RANK_*`).
- The project venv active, so that `python3` and `torchrun` come from `dt-inductor/.venv`.
- An up-to-date build of `torch_spyre._C`. After you merge main or switch branches, rebuild it:

  ```bash
  cd dt-inductor/torch-spyre
  python3 setup.py build_ext --inplace
  ```

  Check the build from a directory outside the repo:

  ```bash
  cd /tmp && python3 -c "import torch, torch_spyre._C"
  ```

For the render step:

- Nothing to install by hand. On first use, `reproduce.sh` creates a venv at `/tmp/diag-venv` and installs `resvg-py` into it.
- Internet access the first time only: `render_png.py` downloads the IBM Plex fonts into `fonts/`.

## Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `TS_DIR` | `../torch-spyre` next to this folder | torch-spyre checkout used for the run |
| `RENDER_VENV` | `/tmp/diag-venv` | venv that holds `resvg-py` |

## What `reproduce.sh` does

1. **Run** (skipped with `--no-run`). Writes the branch and commit of torch-spyre, flex and spyre-comms to `logs.versions.txt`. Then runs `run_ar.py` on two ranks with `DTLOG_LEVEL=debug TORCH_LOGS=output_code`, via `tests/distributed/split_output.sh`, and copies the per-rank logs into `logs/`.
2. **Extract.** `python3 -I extract.py [logs_dir]` parses iteration 1 of both ranks into `data.json`: per control block, the barrier, doorbell, response and callback times, plus queue, pipeline and label. It also writes a readable dump to `extract.out.txt`. All times are in ms after rank 0's `SpyreCommsWorkSchedule(id:2): new`.
3. **Generate.** `python3 -I gen.py` builds `lifecycle.svg`, `timeline.svg` and the control-block table. It fills the `<!--LIFECYCLE-->`, `<!--TIMELINE-->` and `<!--CBTABLE-->` placeholders in `index.src.html` and writes the result to `index.html`.
4. **Render.** `render_png.py [index.html]` renders every `<svg>` in `index.html` at 2× (1920 px wide), once with the light theme and once with the dark theme. It resolves the page's CSS variables and inlines them into each SVG first, because resvg cannot read them from the page.

You can run any step on its own with the command shown in that step.

## Files

| File | Role |
|---|---|
| `reproduce.sh` | Runs all four steps |
| `run_ar.py` | Two-rank driver: `AllReduceWithComputeModule`, iteration 0 is a warm-up, iteration 1 is plotted |
| `extract.py` | logs → `data.json` |
| `gen.py` | `data.json` + `index.src.html` → SVGs + `index.html` |
| `render_png.py` | `index.html` → PNGs |
| `index.src.html` | Page template: the prose, the two hand-drawn SVGs, the CSS |
| `logs/`, `logs.versions.txt` | The run the page text was written from (4 Nov 2026, 18:58 UTC) |

## Before you run on the cards again

- **The run overwrites `logs/`.** The prose in `index.src.html` was written from the saved run and quotes some of its numbers, for example the 0.68 ms rank skew, the 0.12 ms barrier and the 4.17 ms end time. The generated figures and table update on their own; the prose does not. To keep the current page, copy the folder first, or reread the new `extract.out.txt` and update the prose.
- **Timings change from run to run.** Rank skew varies a lot. In one run rank 1 started 0.68 ms early; in another it started 1.04 ms late, and rank 0's RDMA waits stalled.
- **CB tags and queue numbers change too** (105–119 in one run, 27–41 in another). `gen.py` matches control blocks by their position in the sequence, so this is handled.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `AssertionError: CB sequence changed; update ROLES/LONG/DESC/WAITS_ON` | spyre-comms or flex now emits a different set of control blocks. Compare the labels in the error with `LABEL_KEYS` in `gen.py` and update `ROLES`, `LABEL_KEYS`, `LONG`, `PUSH`, `WAITS_ON`, `GROUPS` and `DESC`. The hand-drawn figures and the prose in `index.src.html` probably need updating too. |
| `AttributeError: module 'torch_spyre._C' has no attribute ...` | `_C.so` is older than the Python code. Rebuild it (see Prerequisites). |
| `undefined symbol` when importing `torch_spyre._C` | A build was interrupted and left an empty object file. Run `find torch-spyre/build -name '*.o' -size 0 -delete`, then rebuild. |
| `Disk quota exceeded` during the build | The GPFS home quota is full. Free some space and rebuild, then check for empty `.o` files as in the previous row. |
| `ModuleNotFoundError: No module named 'inductor'` | The test module imports from `tests/inductor`. `run_ar.py` already adds `$TS_DIR/tests` to `sys.path`; check that `TS_DIR` points at a torch-spyre checkout. |
| Fonts fail to download | `render_png.py` needs internet access once. You can also copy `IBMPlexSans-Regular.ttf` (the variable font) and `IBMPlexMono-{Regular,Medium,SemiBold}.ttf` into `fonts/` by hand. |
